## 1. ผีซ้ำ

### วัดของจริงก่อน

สร้างเส้นทาง 6 seed แล้วนับ:

| seed | โหนดสู้ | ผีไม่ซ้ำ | ซ้ำในแถวเดียวกัน |
|---|---|---|---|
| p1 | 28 | 20 | 0 |
| p2 | 28 | 20 | **2** |
| p3 | 28 | 21 | 0 |
| p4 | 28 | 19 | **1** |
| p5 | 28 | 21 | 0 |
| p6 | 28 | 21 | **2** |

เป็น **สองปัญหาคนละเรื่อง** ที่บังเอิญอาการเหมือนกัน:

**1ก. ซ้ำในแถวเดียวกัน — บั๊ก**
บางแถวทางแยกสองทางเป็นผีตัวเดียวกันเป๊ะ กลายเป็นการ์ดสองใบหน้าตาเหมือนกัน
วางคู่กัน = ทางแยกที่ไม่ใช่ทางแยก

สาเหตุ: `pickMonster` ผ่อนเงื่อนไขเป็นลำดับ `fresh → notInRow → base`
พอเงื่อนไข "ห้ามซ้ำกับผีที่เพิ่งสู้" (banned) ตัดตัวเลือกจนเหลือน้อย
ชั้นสุดท้ายจะยอมปล่อยผ่านทั้ง recent และ inRow พร้อมกัน

**แก้:** ยกให้ "ห้ามซ้ำในแถวเดียวกัน" เป็นเงื่อนไขแข็งเท่ากับ banned
ถ้าชนกันจริงจนไม่เหลือตัวเลือก ให้ขยับไป tier ข้างเคียง (สูงขึ้นก่อน)
แทนที่จะยอมซ้ำ — ทำได้เพราะแถวสู้กว้าง 2 และ pool เล็กสุดมี 3 ตน

**1ข. ซ้ำข้ามรัน — ข้อจำกัดของดีไซน์ ไม่ใช่บั๊ก**
28 โหนดสู้ แต่ผีที่ไม่ใช่บอสมีแค่ 24 ตน — **สร้างเส้นทางแบบไม่ซ้ำเลยตั้งแต่ต้นไม่ได้**
และแต่ละ tier มีแค่ 3-5 ตน ยิ่งบีบกว่านั้นอีก

แต่สิ่งที่คุณบอกคือ **"ตัวที่ชนะไปแล้วไม่ควรขึ้น"** ซึ่งแคบกว่ามาก
ผู้เล่นสู้จริงแค่ 13 ไฟต์ปกติ จาก 24 ตน → **เพียงพอ**

**แก้:** จำ `defeatedIds` ไว้ใน state แล้ว**เปลี่ยนโหนดตอนแสดง ไม่ใช่ตอนสร้าง**
`syncOffersFromJourney` เจอโหนดที่ผีถูกฆ่าไปแล้ว ให้สุ่มตัวใหม่จาก tier เดิม
ที่ยังไม่เคยถูกฆ่าและไม่ซ้ำกับอีกฝั่งของแถว

ทำตอนแสดงเพราะแผนที่สร้างล่วงหน้าทั้งเส้น เราไม่มีทางรู้ตั้งแต่ต้น
ว่าผู้เล่นจะเลือกเดินทางไหน — ตัวที่ไม่ได้เดินผ่านก็ไม่ได้ถูกฆ่า

**ผลข้างเคียงที่ต้องยอมรับ:** ผีบนแผนที่ไกลๆ อาจเปลี่ยนตัวระหว่างทาง
ไม่ตรงกับที่เห็นตอนแรก — แต่ตอนนี้แถบเส้นทางแสดงแค่ไอคอน ⚔/☠/⛺
ไม่ได้บอกชื่อผีล่วงหน้าอยู่แล้ว จึงไม่ขัดกับสิ่งที่ผู้เล่นเห็น

**เทสต์:** ไม่มีแถวไหนสองทางเป็นผีตัวเดียวกัน · เดินจนจบรันแล้วไม่เคยเจอผี
ที่ฆ่าไปแล้วซ้ำอีก · ยังซ้ำได้ตาม seed

## 2. หน้าคั่นที่เป็น story

ตอนนี้มีเหตุการณ์ระหว่างทาง (มีทางเลือก) แต่ **ไม่มีเรื่องที่ผูกทั้งรันเข้าด้วยกัน**
ผู้เล่นไม่รู้ว่าออกเดินทางมาทำไม และชนะแล้วได้อะไร

### ต่างจากเหตุการณ์ยังไง

| | เหตุการณ์ (มีแล้ว) | หน้าคั่น (จะทำ) |
|---|---|---|
| โผล่เมื่อไหร่ | สุ่มบนชั้นพัก | จุดที่กำหนดไว้ตายตัว |
| ผู้เล่นทำอะไร | เลือก 2-4 ทาง มีผลต่างกัน | อ่านแล้วแตะไปต่อ |
| หน้าที่ | ให้ตัดสินใจ | บอกว่ากำลังทำอะไรอยู่ |

### จุดที่แทรก (5 จุด)

1. **ก่อนออกเดินทาง** — หลังเลือกคลาส ก่อนเลือกพร (เปิดเรื่อง ต่างกันตามคลาส)
2. **หลังบอสกลาง** (ไฟต์ 7) — จบภาคแรก
3. **ก่อนบอสสุดท้าย** (ไฟต์ 15) — ก่อนเข้าโหนดบอส
4. **ปลดล็อคศึกลับ** — แทนบรรทัด log ที่ตอนนี้ไม่มีใครเห็น
5. **จบรัน** — ก่อนจอสรุป แยกชนะ/ชนะศึกลับ/แพ้

### โครง

- `src/data/packs/base/story_chapters.json` — `{ id, title, text[], scene, classId? }`
  `text` เป็นอาร์เรย์ย่อหน้า เพื่อให้แตะทีละย่อหน้าได้แบบ visual novel
- `state.chapter?: { id, paragraph }` + คำสั่ง `AdvanceChapter` / `SkipChapter`
- โผล่ผ่าน `screenForState` เป็นหน้า `'chapter'` — มาก่อนทุกหน้า
  ยกเว้นหน้าเริ่มเกม (จะได้เทสต์ลำดับหน้าได้เหมือนที่ทำไปแล้ว)
- ใช้ `<Art slot={`chapter/${id}`}>` → ช่องรูปเพิ่มในลิสต์อัตโนมัติ

**ข้อควรระวัง:** อย่าให้ขวางทางคนเล่นซ้ำ — ต้องมีปุ่มข้าม และตัวที่เคยอ่านแล้ว
ควรจำไว้ข้ามรัน (เก็บใน settings ไม่ใช่ใน save ของรัน)

**เทสต์:** ทุกบทมีข้อความจริง · ทุกจุดแทรกมีบทรองรับ · เดินจนจบรันแล้วเจอครบทุกบท
ตามลำดับ · ข้ามได้ทุกบท

## 3. ตัดการประกาศท่าของศัตรู

### ขอพูดตรงๆ ก่อน

การประกาศท่าล่วงหน้า (NotFM 1) คือสิ่งที่ทำให้คอมแบตเป็น **การวางแผน**
ไม่ใช่การเดา — รู้ว่าเทิร์นหน้าโดน 12 จึงตัดสินใจได้ว่าจะตั้งการ์ดหรือเร่งฆ่า
ตัดออกแล้วการตัดสินใจว่าจะโจมตีหรือป้องกันจะกลายเป็นการโยนเหรียญ
โดยเฉพาะกับผีที่ดาเมจกระโดดแรง

แต่มันเป็นเกมของคุณ ถ้าอยากได้จังหวะ "ผลัดกันตี" แบบตรงไปตรงมา ทำได้

### สองทางเลือก

**ทาง ก — ซ่อนแค่หน้าจอ (ถอยกลับง่าย)**
เอา `EnemyIntentBadge` ออก แต่ engine ยังวางแผนเหมือนเดิม
เป็นสวิตช์ตัวเดียว เปลี่ยนใจเมื่อไหร่ก็เปิดคืนได้ ไม่แตะกฎเกม

**ทาง ข — ให้ศัตรูตัดสินใจตอนถึงตาจริง (แนะนำ)**
ตอนนี้ `planEnemyIntent` เลือกไพ่ไว้ตั้งแต่**ท้ายเทิร์นก่อนหน้า** —
จำเป็นเพราะต้องเอาไปโชว์ พอไม่ต้องโชว์แล้ว ย้ายมาตัดสินใจตอน `ResolveEnemyTurn`
จะดีกว่าในเชิงกฎเกม เพราะศัตรู**เห็นกระดานจริงตอนนั้น** — เห็นการ์ดที่เราเพิ่งตั้ง
เห็นเลือดที่เพิ่งเสีย ไม่ใช่ตัดสินใจจากภาพเมื่อเทิร์นที่แล้ว

ผมแนะนำทาง ข เพราะได้ AI ที่ฉลาดขึ้นแถมมาด้วย ไม่ใช่แค่ตัดของออก

### สิ่งที่ต้องระวัง

- `EnemyIntent` ยังต้องอยู่ในระบบ เพราะ `ResolveEnemyTurn` ใช้ `s.enemyIntent.cardIds`
  ตัดสินว่าเล่นไพ่ใบไหน — เปลี่ยนแค่**เวลาที่คำนวณ** ไม่ใช่ลบทิ้ง
- `test/intent.test.ts` (เทสต์ที่ตรวจว่าตัวเลขบน badge ตรงกับดาเมจจริง)
  ต้องเขียนใหม่เป็น "ศัตรูเล่นไพ่ตามที่เลือกไว้ตอนถึงตา"
- ถ้าไม่มีอะไรบอกล่วงหน้าเลย ควรเพิ่ม**สัญญาณตอนโดน**ให้ชัดขึ้นแทน
  (สั่นจอ/แฟลชแรงขึ้นตามดาเมจ) ไม่งั้นเทิร์นศัตรูจะรู้สึกเป็นแค่ตัวเลขลด

## 4. เซฟอัตโนมัติ / เล่นต่อ

### พบว่าเซฟพังอยู่แล้ว — หนักกว่าที่คิด

`autoSave()` ถูกเรียกจริงหลังคำสั่งสำคัญ แต่ **`SaveV1` เก็บข้อมูลไม่ครบ**
ไฟล์ `src/core/save.ts` เขียนไว้ตั้งแต่ก่อนมีระบบใหม่ทั้งหมด:

| ข้อมูล | อยู่ในเซฟไหม | ผลถ้าโหลด |
|---|---|---|
| `journey` | ❌ | ไม่มีเส้นทาง → ตกจอ "ไม่พบเส้นทางของรันนี้" |
| `classId` | ❌ | กลับไปเป็นหมอผีเสมอ |
| `fightCount` | ❌ | ลำดับบอสเพี้ยน |
| `secretBossUnlocked` | ❌ | ศึกลับหาย |
| `story` / `fusionAltar` | ❌ | ค้างกลางเหตุการณ์แล้วโหลด = หลุด |
| `shopRegistry` | ❌ | ร้านที่เคยเจอรีเซ็ต |
| การ์ดในสำรับ | ⚠️ | rehydrate จาก **`cards.json` อย่างเดียว** → **การ์ดคลาส (warrior/nun/medium) กับการ์ดที่ผสานแล้ว หายหมด** |

ข้อสุดท้ายร้ายที่สุด — โหลดเซฟแล้วสำรับถูกตัดทิ้งเงียบๆ โดยไม่มีข้อความอะไรเลย

**เพราะงั้นงานนี้ไม่ใช่ "ต่อปุ่ม Continue" แต่คือซ่อมระบบเซฟก่อน**

### โครงที่เสนอ

**ขั้นที่ 1 — เปลี่ยนวิธีเซฟ**
เลิก whitelist ฟิลด์ทีละตัว เปลี่ยนเป็นเก็บ `GameState` ทั้งก้อน
(ทุกอย่างเป็นข้อมูล primitive อยู่แล้ว — `journey` เป็น plain object, การ์ดเป็น plain object)
ยกเว้นสเตตของคอมแบตที่ตั้งใจไม่เก็บ (`enemy`, `piles`, `pendingEvents`)
เพราะโหลดแล้วกลับมายืนที่แผนที่

ข้อดี: เพิ่มฟิลด์ใหม่ใน `GameState` ทีหลังแล้วเซฟไม่พังตามไปด้วย
ซึ่งเป็นสาเหตุที่มันพังรอบนี้

**ขั้นที่ 2 — เวอร์ชันกับการปฏิเสธเซฟเก่า**
`SAVE_VERSION = 2` เซฟเวอร์ชันต่ำกว่าให้**ปฏิเสธพร้อมบอกเหตุผล** ไม่ใช่โหลดครึ่งๆ
(ตอนนี้ `mapIsReady` รับไว้ได้แล้ว แต่ควรบอกตั้งแต่ตอนโหลด)

**ขั้นที่ 3 — ปุ่มเล่นต่อ**
หน้าเริ่มเกมเพิ่มปุ่ม **"เดินทางต่อ"** เมื่อมี autosave ที่ใช้ได้ พร้อมสรุปย่อ:
คลาส · ศึกที่ n/15 · เลือด · ทอง
ถ้าไม่มีหรือใช้ไม่ได้ → ซ่อนปุ่ม ไม่ใช่ขึ้นแล้วกดไม่ได้

**ขั้นที่ 4 — จังหวะเซฟ**
ตอนนี้เซฟหลัง `CompleteNode` / `ChooseOffer` / ซื้อของ ซึ่งพอ
เพิ่ม `ChooseEventOption` · `FuseCards` · `ChooseLevelUpOption` ให้ครบ
และเซฟตอนออกจากแอป (`AppState` เปลี่ยนเป็น background)

**เทสต์:** เซฟแล้วโหลดได้ state เท่าเดิมทุกฟิลด์ที่สำคัญ (รวม journey/คลาส/การ์ดผสาน) ·
เซฟกลางเหตุการณ์แล้วโหลดกลับมาอยู่ที่เดิม · เซฟเวอร์ชันเก่าถูกปฏิเสธอย่างสุภาพ ·
สำรับหลังโหลดเท่ากับก่อนเซฟเป๊ะ (ข้อนี้ดักบั๊กที่เจอรอบนี้โดยตรง)

## ลำดับที่แนะนำ

1. **ผีซ้ำ** — เล็กสุด เห็นผลทันที และเป็นบั๊กจริง
2. **เซฟ/เล่นต่อ** — ใหญ่สุดแต่สำคัญสุด ตอนนี้เล่นค้างไว้แล้วปิดแอปคือเสียรันทิ้ง
3. **ตัดการประกาศท่า** — กระทบกฎเกม ควรทำตอนที่เซฟนิ่งแล้ว จะได้ทดสอบง่าย
4. **หน้าคั่น story** — งานเนื้อหาเยอะสุด ทำท้ายสุดได้เพราะไม่มีอะไรพึ่งมัน
