## Web visual review before APK

`ui-review.tsx` is an isolated **web-only** harness gated by `EXPO_PUBLIC_UI_REVIEW=1`; normal exports do not activate it. It fetches fixtures from the exported preview folder, never ships embedded saves and never updates a user's game saves. Fixtures are generated by legal engine play (`simulateNight` with observation), including victory/loss and real rest offers. Harness components are the same production components and interactive commands go through `applyCommand`; navigation-only callbacks in the harness end on a review completion page. The normal mobile smoke also exercises actual menu/class/night/start/blessing/route/battle/win/reward navigation.

```sh
npm ci
npm test -- --maxWorkers=2 --testTimeout=60000
npx tsc --noEmit
EXPO_PUBLIC_UI_REVIEW=1 npx expo export --platform web --output-dir /tmp/quiet-web
npx vite-node --config vitest.config.ts scripts/quiet-preview-fixture.ts
npx vite-node --config vitest.config.ts scripts/quiet-review-fixtures.ts
cp /tmp/quiet-review-fixtures.json /tmp/quiet-web/ui-review-fixtures.json
node scripts/preview-mobile.cjs
```

Install Playwright/Chromium as in the workflow or select a browser with `PHIKINHUA_CHROMIUM_PATH`. Output: `docs/previews/quiet-comic/` and `docs/previews/quiet-comic-rest/`. GitHub's web-preview job uploads both folders and the web export. No Android build is triggered on this branch. Eventual native checks still need updated blessing-confirmation and victory-button selectors; physical-device layout remains to be verified in the later APK round.
