# รายงานวิจัยระบบเกม Night of the Full Moon

**ฉบับสำหรับใช้เป็นฐานออกแบบ ผีกินหัว**  
วันที่ตรวจข้อมูล: 13 ตุลาคม 2026  
ขอบเขตหลัก: โหมดผู้เล่นคนเดียว **Full Moon / Classic / Adventure** และระบบต่อเนื่องที่มีผลกับโหมดนี้

---

## 1. บทสรุปผู้บริหาร

*Night of the Full Moon* (ต่อไปใช้ชื่อย่อว่า NotFM) เป็นเกม roguelike deckbuilder ที่ใช้กรอบนิทานหนูน้อยหมวกแดง ผู้เล่นสร้างเด็คระหว่างการผจญภัย ต่อสู้แบบผลัดเทิร์น พบเหตุการณ์สุ่ม และเดินเรื่องผ่านบท/หน้า (chapters/pages) หน้าเดินทางแต่ละครั้งแสดงตัวเลือก 3 หน้าให้เลือก 1 หน้า ระบบเลือกเส้นทางไม่ใช่แค่เปลี่ยนฉาก แต่เป็นการจัดการความเสี่ยงและทรัพยากร: จะสู้เพื่อ EXP/เงิน/โอกาสเก็บของ จะใช้ร้าน/โรงเตี๊ยมปรับเด็ค หรือจะเลือกเหตุการณ์ที่แลก HP กับผลประโยชน์

จุดที่ทำให้เกมรู้สึกเป็น “run ที่มีเรื่องราว” คือระบบหลายชั้นทำงานร่วมกัน:

1. **โครงหน้าเดินทาง 3 ตัวเลือก** ทำให้ผู้เล่นเลือกจังหวะและความเสี่ยงเอง แทนการเห็นแผนที่กว้างที่มีทางเดินมากเกินไป
2. **เด็คและทรัพยากรประจำคลาส** มีแกนร่วม แต่แต่ละคลาสมีวิธีเล่นต่างกันชัด เช่น การ์ดใช้ Action, เวทใช้ Mana, อุปกรณ์สะสมผล, หรือการ์ดสวดที่ตั้งเวลาให้ผล
3. **การต่อสู้ใช้ข้อมูลที่ผู้เล่นมองเห็นและคาดการณ์ได้**: ศัตรูมีเจตนาหรือการกระทำ/การ์ดที่กำลังจะเล่น ผู้เล่นจึงตัดสินใจว่าจะทำดาเมจ ป้องกัน สร้างทรัพยากร หรือขัดจังหวะ
4. **การเติบโตระหว่าง run** เชื่อม EXP → เลเวล → เลือกอัปเกรด, รางวัลการ์ด/ของ/พร และการจัดการเด็คผ่านร้านหรือสถานที่เฉพาะ
5. **เรื่องเล่าหลังการต่อสู้มีผลเชิงระบบ** ใน Normal Mode ตัวเลือกบทสนทนาสะสม Courage และ Reputation ซึ่งส่งผลต่อรางวัลและผู้ที่จะเป็นบอสปลายทาง
6. **ความยากเพิ่มแบบเพิ่มกฎ/ข้อจำกัด** ไม่ได้พึ่งเพิ่ม HP/ดาเมจอย่างเดียว โดยระดับ Hard เพิ่มเงื่อนไขและ Nightmare เพิ่มเหตุการณ์/ผลเสียที่ผู้เล่นเลือกหรือรับมือได้

สำหรับผีกินหัว การนำแนวคิดมาใช้ให้ได้ผลไม่จำเป็นต้องคัดลอกการ์ดหรือธีมนิทาน แต่ควรคัดลอก “วงจรการตัดสินใจ”: **เห็น 3 ทางเลือก → ชั่งความเสี่ยง/ทรัพยากร → ต่อสู้ที่อ่านแผนอีกฝ่ายได้ → รับรางวัลที่เปลี่ยนเด็ค → เห็นผลสะสมต่อ run และเรื่องราว**

## 2. วิธีวิจัยและระดับความเชื่อมั่น

รายงานนี้ตรวจข้อมูลจากหน้าร้าน Steam และประกาศผู้พัฒนาเป็นหลักสำหรับภาพรวม/สถานะปัจจุบัน จากนั้นเทียบกับคู่มือชุมชน Steam และฐานข้อมูลเกมภาษาญี่ปุ่น/อังกฤษสำหรับรายละเอียดเชิงกลไก เช่น เทิร์น การ์ด เส้นทาง และทรัพยากร

| ระดับ | ความหมาย |
|---|---|
| **A — ผู้พัฒนายืนยัน** | หน้าร้านหรือประกาศจาก Giant Games/Steam ของเกม ระบุฟีเจอร์หรือขอบเขตโดยตรง |
| **B — หลายแหล่งชุมชนสอดคล้อง** | คู่มือหรือฐานข้อมูลผู้เล่นอธิบายรายละเอียดตรงกัน แต่ไม่ใช่เอกสารกติกาจากผู้พัฒนา |
| **C — ต้องตรวจในเกมรุ่นปัจจุบัน** | รายละเอียดอาจเปลี่ยนตามแพตช์, DLC, แพลตฟอร์ม หรือคำแปล ควรถือเป็นข้อสังเกต ไม่ใช่ค่าคงที่ |

**ข้อจำกัดสำคัญ:** NotFM พัฒนาต่อเนื่องและมีหลายโหมด ได้แก่ Classic, Red Hood’s Diary, Memory in the Mirror, Treasure Battle, โหมดแข่งขัน/ออนไลน์ และภาคเสริมใหม่ ข้อมูลตัวเลขในวิกิชุมชนบางหน้าล้าสมัย รายงานนี้จึงใช้ Classic/Full Moon เป็น baseline เพราะตรงกับเกมสร้างเด็ค PvE ที่นำมาเทียบกับผีกินหัว และแยกโหมดอื่นออกชัดเจน ไม่ถือว่ารายละเอียดทุกอย่างใช้ร่วมกันได้

## 3. ตัวเกมและขอบเขตของ NotFM ปัจจุบัน

หน้าร้าน Steam อธิบายแกนเกมว่าเป็น deckbuilding game จากเรื่องหนูน้อยหมวกแดง ผู้เล่นต่อสู้กับมอนสเตอร์และสร้างเด็คจากการ์ดที่เก็บระหว่างการผจญภัย หน้าร้านเดิมระบุ 7 คลาส มากกว่า 600 การ์ด และคู่ต่อสู้ 131 ตัว พร้อม random events และตัวเลือกเนื้อเรื่องที่กระทบ Reputation/Courage ตัวเลขเหล่านี้เป็นข้อความบนหน้าร้านที่อาจไม่ได้อัปเดตตาม DLC ล่าสุดทั้งหมด จึงควรอ่านเป็นภาพขนาดของเกมในช่วงข้อมูลเดิม ไม่ใช่จำนวนคอนเทนต์ปัจจุบันแบบรับประกัน【Steam Store, A】

ณ วันที่ตรวจ รายการ DLC บน Steam แสดงหลายสายคอนเทนต์แยกกัน เช่น Classic, Mirror, Wishing และ Treasure Battle ส่วนประกาศผู้พัฒนาล่าสุดพูดถึงการต่อเนื้อเรื่อง Classic ด้วยคลาส Demon Hunter และพูดถึง Treasure Battle ว่าเป็น adventure แบบใหม่ที่มีระบบและฉากท้าทายต่างจาก Classic ดังนั้นเวลาศึกษา NotFM ต้องระบุโหมดทุกครั้ง ไม่ควรรวมจำนวนคลาส/การ์ดหรือกติกาจากทุกโหมดเข้าด้วยกัน【Steam Store; Developer announcement, A】

**ข้อสรุปด้านขอบเขต:** สิ่งที่น่าศึกษาสำหรับผีกินหัวในรอบนี้คือ Classic/Full Moon: run PvE, เลือกหน้า 1 จาก 3, ต่อสู้แบบใช้เด็ค, สะสมการ์ด/พร/ทรัพยากร และเดินเรื่องตามบท ส่วนระบบออโต้เชส, PvP, 1v1 Arena, Treasure Battle ใช้เป็นแรงบันดาลใจเสริมได้ แต่ไม่ใช่ตัวแบบหลัก

## 4. โครงสร้าง run และระบบ Pages

### 4.1 ชั้นของการเดินทาง

Classic นำเสนอการผจญภัยผ่านหนังสือ/บท: **Chapter** เป็นช่วงใหญ่ของเรื่อง และ **Page** คือ encounter หรือกิจกรรมหนึ่งหน้า แหล่งข้อมูลชุมชนระบุว่าผู้เล่นเลือกหนึ่งในสาม Pages ที่แสดงเพื่อเดินหน้าต่อ การเลือกแต่ละครั้งจึงเป็นทางแยกย่อยที่ใช้ตัดสินใจระดับปัจจุบัน มากกว่าเป็นแผนที่โลกเปิด【Full Moon Wiki, B; Gamerch, B】

สิ่งที่ Pages อาจนำเสนอ ได้แก่ การต่อสู้, บอส, ร้าน, รับพร, อัปเกรด/ลบการ์ด, เหตุการณ์, ฟื้นฟู หรือหน้าเฉพาะเงื่อนไข/ความยาก รายชื่อจริงแตกต่างกันตาม Chapter, class, DLC และความยาก ร้าน Grimalkin เป็นหน้าเลือกได้และสินค้าสุ่มตามคลาส; โรงเตี๊ยมลบการ์ดได้โดยมีค่าใช้จ่ายที่เพิ่มขึ้นหลังใช้ครั้งแรกในแต่ละบท; หน้า Fairy Blessing ให้เลือกพรหนึ่งจากชุดตัวเลือก【Grimalkin Shop Wiki; Amnesia Tavern Wiki; Fairy Blessing Wiki, B/C】

### 4.2 ความหมายของการเลือก 1 ใน 3

การเลือก 1 ใน 3 ทำหน้าที่พร้อมกัน 4 อย่าง:

- **คุม pacing:** ผู้เล่นมีอำนาจตัดสินว่าจะสู้หรือพัก/ปรับเด็ค แต่ยังอยู่ในกรอบความยาวของ Chapter
- **คุมความเสี่ยง:** หน้า combat อาจให้ EXP/เงิน/รางวัล แต่ลด HP; หน้า heal/upgrade เสียโอกาสได้ทรัพยากรอื่น
- **สร้างความรู้สึกว่ารันไม่ซ้ำ:** ตัวเลือกถูกสุ่ม/เปลี่ยนไปตามบริบท ทำให้สอง run ไม่จำเป็นต้องผ่านชุดหน้าเดียวกัน
- **ทำให้การตัดสินใจอ่านง่าย:** มีตัวเลือกจำนวนจำกัด ผู้เล่นเปรียบเทียบผลลัพธ์ใกล้ตัวได้โดยไม่ต้องวางแผนบนแผนที่ขนาดใหญ่

**สิ่งที่ไม่ควรตีความเกินหลักฐาน:** “เลือก 1 ใน 3 หน้า” ไม่เท่ากับ “ทุกหน้าต้องทำครบสามเหตุการณ์” และไม่ได้แปลว่าเกมไม่มีหน้าบังคับ บอส/เหตุการณ์เฉพาะบางหน้าถูกกำหนดด้วย Chapter หรือเงื่อนไข การ์ดหน้าแต่ละตัวจึงต้องบอกผู้เล่นชัดว่าเป็นตัวเลือก, เงื่อนไข, หรือหน้าบังคับ

### 4.3 ผลกับผีกินหัว

โมเดล 3 ตัวเลือกต่อจังหวะที่ผีกินหัวกำลังใช้สอดคล้องกับโครงประสบการณ์ของ NotFM ถ้าต้องการให้ใกล้ขึ้น ให้แต่ละตัวเลือกมี **ข้อมูลที่เทียบกันได้**: ประเภทหน้า, ความเสี่ยง/ค่าใช้จ่าย, ผลตอบแทนหลัก และผลที่เปลี่ยนเด็คหรือทรัพยากร ไม่ใช่มีเพียงปุ่มชื่อหน้าที่ดูเหมือนกัน

ตัวอย่าง pattern ที่ยืมได้โดยไม่คัดลอกเนื้อหา:

| ตัวเลือก | ความเสี่ยง | ผลทันที | ผลต่อ run |
|---|---|---|---|
| ต่อสู้ผี | เสีย HP/ทรัพยากรเทิร์น | EXP/เงิน/เลือกการ์ด | เพิ่มความแข็งแกร่งและเปิดทางบอส |
| จุดพัก/พิธี | ใช้ทรัพยากรหรือเสียโอกาส | ฟื้น HP/รับพร | เพิ่มความคงทนหรือปรับแผนเด็ค |
| เหตุการณ์/ร้าน | อาจจ่ายเงินหรือรับผลเสีย | ซื้อ/ลบ/อัปเกรด/แลกเปลี่ยน | แก้จุดอ่อนของเด็คหรือรับความเสี่ยงระยะยาว |

## 5. ระบบต่อสู้และการ์ด

### 5.1 วงจรเทิร์นพื้นฐาน

ฐานข้อมูลคู่มือญี่ปุ่นอธิบายการต่อสู้เป็น turn-based: เริ่มด้วยเทิร์นผู้เล่น แล้วจึงเป็นเทิร์นศัตรู ผู้เล่นชนะเมื่อ HP ศัตรูเหลือ 0; ในต้นเทิร์นจั่วการ์ดจนถึง hand limit และลำดับเด็คสุ่ม ทำให้การสร้างเด็คมีความสำคัญ【Gamerch basic rules, B】

ระบบทรัพยากรหลักใน Classic มีอย่างน้อย:

- **HP / Max HP:** ตัวกำหนดการอยู่รอดข้ามการต่อสู้และเหตุการณ์
- **Mana (MP):** ใช้การ์ดเวท; ตามคู่มือบางชุด MP เริ่มต้นมีอยู่และไม่ได้ฟื้นทุกเทิร์นโดยอัตโนมัติ ต้องมีการ์ด/อุปกรณ์สร้างหรือเพิ่ม
- **Action:** ใช้การ์ดประเภท Action; ค่าพื้นฐานคืนเมื่อต้นเทิร์น และอาจเพิ่มจากพร/เลเวล
- **EXP / Level:** ได้จากศัตรูและบางเหตุการณ์; เมื่อถึงเกณฑ์ เลเวลอัปและเลือกการเติบโต
- **Skill:** ความสามารถประจำคลาสที่มี cooldown เป็นจำนวนการต่อสู้ตามความสามารถ
- **Gold:** ใช้กับร้าน/บริการ และจึงมีต้นทุนโอกาสกับการรักษา HP หรือปรับเด็ค

ข้อมูลเหล่านี้อิงคู่มือชุมชนและอาจแตกต่างตามคลาสหรือ DLC【Gamerch basic rules, B】

### 5.2 ประเภทการ์ด

คู่มือ Gamerch แจกแจงชนิดการ์ดใน Classic เช่น Action, Attack, Equipment, Mana, Prayer, Counter, Spell และการ์ดพิเศษร้านค้าที่ไม่ลงเด็ค การแบ่งประเภทนี้ทำให้ผู้เล่นเห็น “บทบาท” ของการ์ดและแหล่งใช้ทรัพยากร ไม่ใช่แค่เห็นตัวเลขดาเมจ【Gamerch, B】

| ประเภท/แกน | หน้าที่หลัก | ประเด็นด้านการออกแบบ |
|---|---|---|
| Attack | สร้างความเสียหายโดยตรง | อ่านผลทันที เหมาะเป็นแกนพื้นฐาน |
| Action | ใช้ Action เพื่อทำผลเสริม/โจมตี | เปิดการต่อเนื่อง แต่จำกัดด้วย Action |
| Spell | ใช้ Mana ทำผลเวท | เป็นทรัพยากรอีกแกนที่ต้องบริหาร |
| Equipment | ติดตั้งและคงผลไว้ | การเลือกช่องอุปกรณ์เปลี่ยนแผนทั้ง run |
| Prayer | ตั้งจำนวนรอบรอผล/ปรับกำลังผล | สร้างการวางแผนล่วงหน้าและความเสี่ยง |
| Counter | ตอบโต้การ์ด/การกระทำศัตรู | ทำให้ข้อมูลเจตนาศัตรูมีคุณค่า |
| Shop-only | ใช้ผลเมื่อซื้อ ไม่เข้าเด็ค | ลดความสับสนระหว่างไอเท็มกับการ์ดต่อสู้ |

### 5.3 จั่วและขนาดมือ

> **แก้ไข 13 ต.ค. 2026:** ฉบับแรกสรุปว่า "จั่วจนเต็ม hand limit" ซึ่งไม่ถูก ภาพหน้าจอเกมจริง (`evidence/notfm-hand-stats-lv3.jpg`, ระดับความมั่นใจ **A**) แสดงสองค่าแยกกัน: **Max Hand Card** (มือสูงสุด) และ **Cards Per Turn** (จั่วต่อเทิร์น) เริ่มที่ 2 ทั้งคู่ และที่เลเวล 3 ยังเป็น 2 — การเพิ่มสองค่านี้จึงหายาก

เกมจริงแยก "มือสูงสุด" กับ "จั่วต่อเทิร์น" ออกจากกัน (ภาพหน้าจอ, A) ส่วนคู่มือ Gamerch เขียนว่าต้นเทิร์นจั่วการ์ดตามจำนวน "手札上限" ซึ่งกำกวมเรื่องคำแปล จึงใช้ภาพหน้าจอเป็นหลัก การ์ด/สถานะที่เพิ่มหรือลดการจั่วในเทิร์นถัดไปมีอยู่จริงตามคู่มือ【Gamerch, B】

**ข้อสังเกตเชิงออกแบบ:** ระบบนี้สร้างความแตกต่างระหว่าง “มีการ์ดมากในเด็ค” กับ “เห็นการ์ดมากในเทิร์น” และทำให้การ์ดที่ดึงการ์ด/ใช้ทรัพยากร/สร้าง Action เป็นตัวคูณประสิทธิภาพ การจำกัดมือช่วยกันวงจรจั่วไม่จบ แต่คลาสที่เน้นจั่วอาจมีเครื่องมือเพิ่มเพดานหรือใช้การ์ดจำนวนมากต่อเทิร์น

### 5.4 สถานะและความสามารถอ่านเกม

เกมมีชุดสถานะป้องกัน/โจมตี/ขัดจังหวะที่ขยายการตัดสินใจ เช่น Block/Defense, Poison, Burn, Freeze, Vulnerability, Counter/Cancel, Dodge, Healing, Damage cap, Piercing และสถานะที่ทำดาเมจเมื่อเล่นการ์ด คู่มือรายละเอียดสถานะหลายสิบชนิดในฐานข้อมูลปัจจุบัน【Gamerch combat statuses, B】

การเรียนรู้จากระบบนี้ไม่ใช่การนำสถานะทั้งหมดมาใส่ แต่คือการทำให้สถานะแต่ละแบบมีจังหวะชัด เช่น:

- **เกิดเมื่อไร:** ต้นเทิร์น, เมื่อเล่นการ์ด, หลังโจมตี, ตอนจบเทิร์น
- **อยู่กี่ครั้ง/กี่เทิร์น:** ตัวเลขบนไอคอนต้องอธิบายได้
- **รับมืออย่างไร:** รอให้หมด, ป้องกัน, ลบล้าง, หรือใช้ประโยชน์จากมัน
- **มีผลกับการตัดสินใจใด:** เล่นการ์ดเพิ่มหรือหยุด, เร่งฆ่าหรือป้องกัน, เก็บการ์ดไว้หรือใช้ตอนนี้

### 5.5 เจตนาศัตรูและการถือการ์ด

แหล่งอ้างอิงที่เปิดได้ในรอบนี้ยืนยันโครงสร้างเทิร์นและการ์ดอย่างชัด แต่ไม่ให้เอกสารทางการครบทุกกรณีของ AI/hand persistence ในทุกคลาส/มอนสเตอร์ จึงไม่ควรสรุปว่าศัตรูทุกตัวใช้กติกามือแบบเดียวกัน ข้อสังเกตจากวิกิและคู่มือผู้เล่นชี้ว่าศัตรูมีชุดการ์ด/พฤติกรรมเฉพาะและตัวแปรของบอสจำนวนมาก แต่การจัดการมือของศัตรูควรตรวจจากเกมจริงและแยกตาม enemy archetype ก่อนยกเป็นกฎสากล【Full Moon Wiki; Gamerch, B/C】

**ข้อเสนอสำหรับผีกินหัว:** ถ้าจะเพิ่มระบบเก็บการ์ดศัตรูค้างมือแบบ v34 ที่กำลังทำ ให้สื่อสารผ่าน 3 สิ่งให้ครบ: (1) การ์ดที่ศัตรูถืออยู่มองเห็นตรงตำแหน่ง HUD, (2) ผู้เล่นเข้าใจว่า AI จะใช้หรือเก็บไว้เพราะอะไร, (3) การ์ดค้างมือมีเพดาน/ทางระบาย เพื่อไม่ให้เกมดูเหมือนศัตรูโกงหรือสุ่มรอคอมโบ

## 6. ความก้าวหน้าระหว่าง run

### 6.1 EXP และการเลเวลอัป

ผู้เล่นได้ EXP จากการชนะศัตรูและบางเหตุการณ์ เมื่อถึงเกณฑ์จะเลเวลอัป ข้อมูลคู่มืออธิบายว่าเลเวลอัปเกี่ยวข้องกับ HP/Max HP, MP หรือ Action และมีตัวเลือกช่วยปรับตัวละคร/เด็ค; รายละเอียดรางวัลที่แน่นอนขึ้นกับระดับและคลาส【Gamerch, B】

ในเชิง pacing บอสประจำบทเป็นหมุดความก้าวหน้าที่สำคัญ และคู่มือชุมชนระบุว่าบอสแต่ละบทให้ EXP ในระดับที่ทำให้เลเวลเพิ่มพอดีในกติกาบางเวอร์ชัน จึงเกิดจังหวะ “สร้างพลังช่วงก่อนบอส → เจอบอสเป็นการทดสอบ build”【Gamerch, B/C】

### 6.2 Reward หลังชนะ

รางวัลหลัง combat ไม่ได้จำกัดแค่การ์ดใบใหม่ คู่มือและรีวิวระบุการผสมรางวัล/ผลหลังต่อสู้ เช่น EXP, Gold, การ์ดหรืออัปเกรด และบางครั้งบทสนทนาให้เลือกผลต่อ Courage/Reputation/HP/Gold/การ์ด【Gamerch; Steam Guide; Pocket Gamer, B】

**ประเด็นสำคัญ:** การให้ผู้เล่นเลือกจากรางวัลหลายใบ/หลายผลทำให้ “ชนะ” เป็นจุดตัดสินใจอีกครั้ง ผู้เล่นไม่ได้ถูกบังคับให้เพิ่มการ์ดทุกครั้ง ซึ่งช่วยคุมขนาดเด็คและเปิดให้เลือกการ์ดตาม build ที่กำลังเกิดขึ้น

### 6.3 การจัดเด็คและเศรษฐกิจ

ระบบนอกสนามรบมีบริการหลายแบบที่แก้เด็คคนละมิติ:

- **ร้าน:** ซื้อการ์ด/ของที่มีให้ตามคลาสและการสุ่ม ใช้ Gold แลกความสม่ำเสมอ
- **โรงเตี๊ยม/ลบการ์ด:** เอาการ์ดที่ไม่ต้องการออก; ในคู่มือมีค่าใช้จ่ายเพิ่มตามครั้งหลังจากครั้งแรกฟรีใน Chapter
- **ช่างตีเหล็ก/อัปเกรด:** เพิ่มระดับหรือเปลี่ยนความแรงของการ์ด; ใช้ทรัพยากรและตำแหน่งหน้าเป็นต้นทุน
- **Blessing:** เลือกพรที่มีผลต่อ combat หรือ run; หน้ารับพรให้เลือกจากตัวเลือกแทนการรับสุ่มทั้งหมด
- **อุปกรณ์:** มีช่องจำกัดและติดตั้งก่อน combat ทำให้การเลือกอุปกรณ์เป็นการวางแผนล่วงหน้า ไม่ใช่เอฟเฟกต์ชั่วคราว

รายละเอียดสถานที่และค่าใช้จ่ายอาจต่างกันตามโหมด/แพตช์ ควรใช้หลักการแยกบริการตาม “ซื้อ/ลบ/อัปเกรด/เพิ่มพลัง” มากกว่าคัดลอกตัวเลขราคา【Grimalkin Shop Wiki; Amnesia Tavern Wiki; Gamerch, B/C】

**การประยุกต์กับผีกินหัว:** เก็บประเด็น backlog ที่ผู้ใช้ระบุไว้ เช่น ซื้อแล้วต้องยืนยัน, ร้านต้องคงหน้าอยู่จนผู้เล่นปิด, ร้านแสดงการ์ดเหมือนในเด็คและระดับเดียวกัน, แยกการสละกับปลุกเสกให้ชัด ระบบ NotFM สนับสนุนหลักคิดว่าหน้าเศรษฐกิจคือการเลือกเชิง build จึงควรแสดงราคา/ผล/ผลถาวรให้ครบก่อนยืนยัน

## 7. เรื่องเล่าและผลเชิงระบบ

ใน Normal Mode หลังชนะศัตรูบางตัว ผู้เล่นจะได้เลือกบทสนทนา 2–3 ตัวเลือก ตัวเลือกอาจเพิ่ม/ลด Courage หรือ Reputation หรือเปลี่ยน HP/Gold/การ์ด/ทรัพยากร คู่มือผู้เล่นระบุว่าหนึ่งบทมีบทสนทนาจำนวนจำกัด และตัวเลือกที่เคยเลือกแล้วมีสัญลักษณ์ช่วยจำ【Steam Community Guide, B】

ค่าสะสมทำให้เรื่องเล่ามีผลต่อ run:

- Reputation สูงกว่าความกล้าหาญเป็นแนวทางไปยังบอส Witch ในเงื่อนไขที่เกี่ยวข้อง
- Courage มากกว่าหรือเท่ากับ Reputation ทำให้เผชิญ Werewolf ได้
- คะแนนบางระดับให้ผลตอบแทน เช่น Reputation ให้ Gold และ Courage เพิ่ม Max HP
- เส้นทาง/บอสเพิ่มเติมอาจปลดล็อกเมื่อทำเงื่อนไขอื่นสำเร็จ เช่น ผ่านบอสหรือเหตุการณ์ที่เกี่ยวข้อง

ข้อมูลนี้ได้รับการอธิบายในคู่มือชุมชน ไม่ใช่หน้ากติกาทางการ และมีความเสี่ยงเรื่องคำแปล/เวอร์ชัน【Steam Community Guide; Gamerch, B/C】

**หลักออกแบบที่ยืมได้:** เหตุการณ์หลังสู้ควรทำให้ผู้เล่นเลือก “บุคลิก/วิธีแก้ปัญหา” แล้วเกมตอบสนองเป็นระบบ ไม่ใช่บทสนทนาตกแต่งอย่างเดียว สำหรับผีกินหัวอาจทำเป็นแนวทาง เช่น เมตตา/ไสยศาสตร์/เอาตัวรอด ที่สะสมไปเปลี่ยนพร, เหตุการณ์, สภาพศัตรู, หรือบอสในช่วงท้าย โดยต้องไม่เพิ่มความซับซ้อนเกินกว่าที่ผู้เล่นอ่านผลได้

## 8. ความยากและการเล่นซ้ำ

Classic มี Normal และ Hard เป็น baseline ในแหล่งคู่มือ; Hard มีการไต่ระดับย่อยและข้อจำกัดเพิ่มเติม ข้อมูลญี่ปุ่นปัจจุบันอธิบาย Hard tiers ที่เพิ่มความแข็งแกร่งศัตรู, ลดการฟื้นฟู/ขนาดมือ, เพิ่มต้นทุนร้าน หรือใส่เงื่อนไขพิเศษ ขณะที่ Nightmare เพิ่มหน้าเหตุการณ์/ผลเสียเพิ่มเติม【Wiki* Japan; Gamerch, B/C】

จุดออกแบบคือความยากเพิ่มหลายแกน:

| แกน | ตัวอย่างผล |
|---|---|
| ความแรงศัตรู | HP/ดาเมจ/พฤติกรรมสูงขึ้น |
| เศรษฐกิจ | ร้านแพงขึ้น, รางวัลหายากขึ้น |
| ทรัพยากรผู้เล่น | ฟื้นน้อยลง, มือเล็กลง, HP/Action ถูกจำกัด |
| กฎของ run | มีสถานะ/เหตุการณ์พิเศษที่บังคับให้เปลี่ยนแผน |
| ความรู้และ mastery | ปลดล็อกบอส/พร/คอนเทนต์หลังผ่านเงื่อนไข |

**ผลต่อผีกินหัว:** ระดับ Easy → Hard 5 ที่ทีมเคยหารือควรเพิ่ม “แรงกดดันคนละชนิด” ในแต่ละขั้น ไม่ใช่เพิ่ม HP/ดาเมจทุกครั้ง รูปแบบที่อ่านง่ายคือ: 1) ฝึกกติกา, 2) เพิ่มแรงกดดันทรัพยากร, 3) เพิ่มลูกเล่นศัตรู, 4) เพิ่มความเสี่ยงเส้นทาง/เหตุการณ์, 5) ทดสอบ build ด้วยบอสใหญ่และกฎพิเศษหนึ่งชุด

## 9. คลาสและตัวตนของ build

หน้าร้านเดิมเน้นคลาสหลากหลายและการ์ดจำนวนมาก แต่ไม่ใช่ทุกคลาสจะเล่นเหมือนกัน แหล่งข้อมูลจากชุมชนและคู่มือชี้รูปแบบการออกแบบคลาส เช่น:

| รูปแบบตัวตน | ตัวอย่างจาก NotFM | จุดเล่นที่สร้างความต่าง |
|---|---|---|
| อาวุธ/อุปกรณ์และป้องกัน | Knight | ใช้อุปกรณ์/เกราะเป็นทุน สะสมพลังและอยู่รอด |
| Action, จั่ว, หลบ/พิษ | Ranger | ใช้ Action ต่อเนื่อง, วนเด็ค, สร้างดาเมจหลายครั้ง |
| Mana และเวท | Witch | ใช้ทรัพยากรเวท/เร่งการเล่นเวทและทำดาเมจสูง |
| Prayer/ตั้งเวลาผล | Nun | เลือกเวลารอให้ผลของคำอธิษฐานแรงขึ้น แลกกับการทนอยู่รอด |
| Potion/สถานะ | Apothecary | ผสมผลเวท/พิษ/สถานะเพื่อปั้นความเสียหายหรือควบคุม |
| Rage/การใช้การ์ด | Werewolf | สร้างพลังตามการต่อสู้และใช้การ์ดที่ถูกกำจัด/แปลง |
| กลไก/ชิ้นส่วน/Exhaust | Mechanic | แปลงการใช้หรือกำจัดการ์ดเป็นการประกอบเครื่อง/ระเบิด/เกราะ |

ตารางนี้เป็นการจัดหมวดเชิงกลไกจากคู่มือ/การสนทนาผู้เล่น ไม่ใช่ taxonomy ทางการ และแต่ละคลาสมีหลาย build【Night of the Full Moon Wiki; Reddit class discussions; Wiki* Japan, B/C】

**บทเรียนสำคัญ:** ความต่างของคลาสมาจาก “กฎหรือทรัพยากรเฉพาะ” มากกว่าการเปลี่ยนตัวเลขการ์ด ถ้าผีกินหัวมีสี่อาชีพ แต่ละอาชีพควรตอบคำถามได้ว่า:

1. ทรัพยากร/กฎที่มีเฉพาะคืออะไร?
2. ในเทิร์นหนึ่งผู้เล่นอยากทำอะไรเป็นลำดับ?
3. การ์ดแบบไหนทำให้ build นั้นเติบโต?
4. จุดอ่อนที่คู่ต่อสู้หรือเหตุการณ์ใช้กดดันคืออะไร?
5. ผู้เล่นมือใหม่เห็นสัญญาณใดแล้วเข้าใจวิธีเล่น?

## 10. UX ที่ควรศึกษา

### 10.1 หน้าเลือกเหตุการณ์

- แสดงตัวเลือกเป็นหน่วยเปรียบเทียบกันได้และมีปุ่มยืนยันที่ชัด
- ใช้ภาพ/ชื่อของ encounter ทำให้ผู้เล่นคาดเดาประเภทหน้าได้
- เมื่อเปิดหน้าร้านหรือเหตุการณ์ ให้ผู้เล่นมีทางออกที่ไม่ทำให้เกิดการข้าม/เริ่มต่อสู้โดยไม่ตั้งใจ
- แยก “เข้าไปดู”, “ซื้อ/เลือกผล” และ “ออกจากหน้า” เป็นคนละการกระทำถ้าผลมีค่าใช้จ่ายหรือถาวร

### 10.2 หน้าต่อสู้

- แสดงทรัพยากรที่จำเป็นต่อการตัดสินใจ ได้แก่ HP, การป้องกัน, Action/Mana, สถานะ และการ์ดในมือ
- ผู้เล่นควรเห็นสิ่งที่ศัตรูจะทำก่อนจบเทิร์น หากระบบ AI ออกแบบให้คาดการณ์ได้
- การเล่นการ์ดต้องแสดงต้นทุน/เป้าหมาย/ผลล่วงหน้า
- พื้นที่ศัตรูต้องไม่ถูก HUD หรือ popup บังจนอ่านภาพตัวละครไม่ได้
- ประวัติการ์ด/ผลล่าสุดช่วยให้เข้าใจเหตุการณ์ที่เกิดเร็ว โดยเฉพาะเมื่อมี status tick, minion หรือการ์ดหลายใบทำงานต่อกัน

### 10.3 ระบบคำอธิบาย

- ไอคอนสถานะต้องคลิก/แตะดูรายละเอียดหรือมี tooltip ที่ระบุผลและระยะเวลา
- สัญลักษณ์บนการ์ดต้องสื่อชนิด/ต้นทุนอย่างคงที่
- ประวัติที่เลือกในอดีตหรือผลที่สะสมควรมีสัญลักษณ์บอกสถานะ เพื่อให้การเล่นซ้ำไม่ต้องจำทุกเหตุการณ์

## 11. สิ่งที่ควรหยิบไปใช้กับผีกินหัว

| ลำดับ | หลักจาก NotFM | แนวทางสำหรับผีกินหัว | เหตุผล |
|---|---|---|---|
| 1 | หน้าทางเลือก 3 ตัวเลือกทำให้ผู้เล่นคุม run ได้ | ทุกหน้าแสดงประเภท/ความเสี่ยง/ผลทันที; แยกหน้า optional กับ mandatory | ทำให้การเลือกมีความหมายและไม่ทำให้ผู้เล่นหลงทาง |
| 2 | Combat reward เป็นการเลือก build | หลังสู้ให้เลือกจากการ์ด/พร/เงินแบบมีข้อมูลพอ และมีตัวเลือกไม่รับเมื่อเหมาะ | ป้องกันเด็คพองและช่วยให้ build มีตัวตน |
| 3 | คลาสแตกต่างด้วยทรัพยากร/กฎ | นิยาม identity ต่อคลาสเป็น 1–2 แกนหลักก่อนเพิ่มการ์ด | ผู้เล่นเข้าใจคลาสและวางแผนได้ |
| 4 | เรื่องเล่ามีผลต่อเส้นทาง | ให้ทางเลือกเหตุการณ์เปลี่ยนค่าสะสมที่นำไปสู่เหตุการณ์/บอส/รางวัล | ทำให้เนื้อเรื่องเชื่อมกับ gameplay |
| 5 | ความยากเพิ่มกฎหลายด้าน | เพิ่มแรงกดดันเป็นขั้น เช่น มือ/ร้าน/สถานะ/ศัตรูเฉพาะ ไม่บวก HP อย่างเดียว | ได้ mastery curve ที่มีความหลากหลาย |
| 6 | พร/อุปกรณ์มีผลต่อหลายการต่อสู้ | แสดงผลถาวร/ผลเฉพาะการต่อสู้ชัด แยกหมวดไอคอน | ลดความสับสนและเพิ่มความคาดหวังเชิง build |
| 7 | ระบบศัตรูควรอ่านได้ | ศัตรูมี intent, hand history หรือคิวการ์ดเมื่อเหมาะ | เพิ่มการวางแผนและลดความรู้สึกว่าสุ่มโกง |
| 8 | หน้าร้านและบริการคือส่วนหนึ่งของ build craft | ใช้ confirm สำหรับซื้อ/ขาย/อัปเกรด/ลบ; ปิดด้วย X อย่างชัดเจน | ตรงกับ backlog UX ที่ผู้เล่นแจ้งไว้แล้ว |

### ลำดับทำงานที่แนะนำ

**P0 — กติกาและความชัด:** จบระบบ hand/draw ของผู้เล่นและศัตรู, บอก intent, แสดง card history, ทำให้ปุ่มข้าม/ยืนยัน/ปิดมีความหมายตรงกัน  
**P1 — วงจร build:** reward หลังสู้, ร้าน/ลบ/อัปเกรด, พรและอุปกรณ์ต้องมีผลชัดและไม่ถี่จนลดค่าของมัน  
**P2 — run structure:** ตรวจสัดส่วนศัตรู/เหตุการณ์/ร้าน/พักในหนึ่งรอบ ให้ความยาวใกล้เป้าหมาย 60 นาทีและมีหมุดบอส  
**P3 — replayability:** เพิ่มความยาก 5 ระดับและเส้นทางเรื่อง/บอสตามพฤติกรรมผู้เล่น หลังแกนต่อสู้เสถียร  
**P4 — content scale:** เพิ่มการ์ดศัตรูและ build เฉพาะผี โดยทุกการ์ดต้องมีบทบาทเดี่ยวที่ใช้ได้ ไม่พึ่งระบบคอมโบที่ถูกถอดออก

## 12. สิ่งที่ไม่ควรคัดลอกตรง ๆ

1. **จำนวนการ์ด/ศัตรู:** ตัวเลขใหญ่ของ NotFM เกิดจากการสะสมคอนเทนต์หลายปีและ DLC; ผีกินหัวควรลงทุนกับความแตกต่างและความอ่านง่ายก่อนจำนวน
2. **เศรษฐกิจ/ค่า HP:** ราคาหรือค่ารักษาของ NotFM พึ่งโครงสร้าง Chapter และความยาว run ของเขา ตัวเลขเดียวกันอาจใช้กับรอบ 60 นาทีของเราไม่ได้
3. **ระบบสถานะทั้งหมด:** สถานะมากเกินไปทำให้ HUD แน่นและอธิบายยาก ต้องเลือกเฉพาะที่สร้างการตัดสินใจต่างกัน
4. **ความสุ่มโดยไม่มี telegraph:** ความสุ่มของ Pages ใช้ได้เมื่อผู้เล่นมีข้อมูลพอจะชั่งความเสี่ยง; ความสุ่มของการโจมตีที่ไม่บอกล่วงหน้าอาจทำให้รู้สึกว่าแพ้เพราะโชค
5. **ระบบคลาส/โหมด DLC:** กติกาที่อยู่ใน Diaries, Mirror, Treasure Battle หรือโหมดออนไลน์ไม่ควรถูกถือเป็น baseline ของ Classic
6. **การเพิ่มความยากด้วยตัวเลขอย่างเดียว:** ให้เพิ่มแรงกดดันเชิงกฎอย่างมีลำดับและสื่อสารก่อนเข้า run

## 13. คำถามที่ควรตอบจากการเล่นจริงรอบถัดไป

การค้นเว็บอธิบายกรอบและกติกาจำนวนมาก แต่คำถามเหล่านี้ควรตรวจด้วยการเล่น NotFM เวอร์ชันปัจจุบัน โดยเฉพาะหลังแพตช์ใหม่:

- สาม Pages ที่เสนอในแต่ละครั้งถูกสุ่มจาก pool ตาม Chapter, class, ความยาก หรือ state ใดบ้าง?
- หน้า/ศัตรูแบบไหนเป็น mandatory และเงื่อนไขใดทำให้มีหน้าพิเศษ?
- ผู้เล่นได้เลือกการ์ดหลังชนะกี่ตัวเลือกในแต่ละชนิดการต่อสู้ และมีกรณีไม่รับหรือ skip หรือไม่?
- การเก็บการ์ดค้างมือมีผลระหว่างเทิร์นกับศัตรูทุกตัวหรือเฉพาะบางตัว?
- ศัตรูเผย intent อย่างไร และ intent ผูกกับการ์ดจริงหรือเป็นข้อความ/สัญลักษณ์คาดการณ์?
- ร้าน/พร/โรงเตี๊ยม/ช่างตีเหล็กปรากฏถี่แค่ไหนต่อ Chapter ในความยากปัจจุบัน?
- เส้นทางบอสจาก Courage/Reputation ทำงานอย่างไรหลังอัปเดต Classic/DLC ล่าสุด?
- ในหนึ่ง run ปัจจุบันผู้เล่นใช้เวลากี่นาทีต่อคลาส/ระดับความยาก?
