## ข้อสรุป

branch นี้มีแกนระบบของเกมสร้างเด็คแบบ NOTFM อยู่แล้วมากกว่าที่รายงานวิจัยฉบับแรกประเมินจากประวัติเดิมอย่างชัดเจน ไม่ควรเริ่มเพิ่ม Pages, Mana, Prayer, Counter, อาชีพ, สกิล, ความกล้า/บุญ หรือความยากใหม่ซ้ำอีก งานถัดไปควรเน้น **ทำให้ระบบปัจจุบันมองเห็นครบ → ทำให้ build เริ่มทำงานสม่ำเสมอ → เพิ่มเหตุการณ์/พรที่เปลี่ยนวิธีเล่น → จูนอาชีพและความยาก**

พบช่องว่างสำคัญจากโค้ด:

1. หน้าสำรับใช้ชนิดการ์ดเก่า ทำให้ไม่แสดง Action / Spell / Mana / Prayer / Counter
2. ระบบอุปกรณ์และบทสวดทำงานแล้ว แต่หน้าต่อสู้ยังไม่มีรายการอุปกรณ์ที่สวมและคิวบทสวดนับถอยหลัง
3. ยังไม่มีการเลือกสวมอุปกรณ์ก่อนเริ่มไฟต์ ซึ่งเป็นส่วนสำคัญของ equipment build ใน NOTFM Classic
4. เส้นทางปกติใช้เหตุการณ์คงที่เพียง run_story_1–3 แม้มีข้อมูลเรื่องทั้งหมด 22 รายการและมี 12 เหตุการณ์อิสระที่นำมาคัดใช้ได้
5. พรแพนโดรา 7 แบบมีผลตอนรับพรเท่านั้น ยังขาดผลดี/ข้อเสียที่ทำงานต่อเนื่องและเปลี่ยนวิธีเล่น
6. การเติบโตทรัพยากรหลักมีอยู่ แต่โอกาสเข้าถึงยังแคบ: รางวัลเลเวลไม่มี AP/Mana/Draw, ส่วน AP ถาวรผูกกับพรแพนโดราที่ปลดล็อก 6 คืน
7. การปลดล็อกพรคำนวณจากประวัติ 60 รันล่าสุด จึงไม่ใช่ความก้าวหน้าสะสมถาวรอย่างแท้จริง
8. handoff ระบุช่องว่างบาลานซ์นักรบ/คนทรงและระดับ 5; ยังต้องตรวจเล่นจริงและวัดเวลารัน 60 นาที

นี่เป็น **การตรวจโค้ดและข้อมูล + ตรวจผล CI ที่มีอยู่** ไม่ใช่รายงานว่าทุกหน้าผ่านการเล่นบน Android ในรอบนี้ ไม่มีการแก้โค้ดเกม, commit, push หรือสั่ง build เพิ่ม

### G04 — เลือกสวมอุปกรณ์ก่อนเข้าไฟต์ (P1, ต้องออกแบบบาลานซ์คู่กัน)

NOTFM Classic มีการกำหนดอุปกรณ์ในช่องก่อนเข้าไฟต์ อุปกรณ์ที่อยู่ในช่องเริ่มทำงานตั้งแต่เปิดไฟต์ ส่วนที่เหลืออยู่ในเด็ค ตามคู่มือชุมชน [Equipment slot](https://night-of-the-full-moon.fandom.com/wiki/Equipment_slot) และ [Full Moon](https://night-of-the-full-moon.fandom.com/wiki/Full_Moon) ความมั่นใจระดับ B

**ของเรา:** `beginPlayerFight` สับ masterDeck ทั้งกองแล้วตั้ง equipped ว่าง ทุกไฟต์จึงต้องจั่วอุปกรณ์แล้วเล่นใหม่ จำนวนช่องเพิ่มได้จริง แต่ยังไม่ช่วยให้ build เริ่มอย่างสม่ำเสมอ นี่เป็นความต่างเชิงกลไกที่สำคัญกว่าการเพิ่มจำนวนอุปกรณ์

**งานที่เสนอ:** หน้าเตรียมสวมอุปกรณ์จากสำรับตามจำนวนช่อง; เริ่ม combat ย้ายสำเนาที่เลือกเข้า equipped แทน draw pile และยิง equip trigger ครั้งเดียว; ของเกินช่องคงในเด็ค; เลือกเปลี่ยนระหว่างไฟต์ได้

**ประเด็นต้องจูน:** นักรบได้ Block จาก equip อยู่แล้วและค่อนข้างแรงในผลซิม หากเพิ่ม pre-equip ต้องคิด passive/อุปกรณ์/HP ศัตรูพร้อมกัน ไม่ควรเพิ่มความได้เปรียบให้ทุกอาชีพโดยไม่ตรวจผล

**เกณฑ์ตรวจ:** ไม่มีการสร้างสำเนาถาวรซ้ำ; ช่องที่เลือกคงข้ามไฟต์; trigger ไม่ยิงซ้ำเมื่อเปิดรายละเอียดหรือ resume; equipment build ทำงานในเทิร์นแรกอย่างคาดการณ์ได้

หลักฐานฝั่งเรา: [commands / beginPlayerFight](https://github.com/saranaauttama-afk/PhiKinHuaV6/blob/bce58b93333e02e9ca214c0468e59bd5d89fada1/src/core/commands.ts)

### G05 — Random events และผลการเลือกที่ต่อเนื่อง (P1)

งานวิจัยยืนยันว่าการผจญภัยและเหตุการณ์สุ่มเป็นส่วนของ NOTFM และตัวเลือกเรื่องเล่าเปลี่ยนค่า Courage/Reputation/ทรัพยากรได้ ของเรามีเรื่องเล่าและสองค่าดังกล่าวแล้ว แต่ `startAdventure` สร้างเพียง `run_story_${night}` คืนละหนึ่งเรื่องทุก run

ข้อมูลมี 12 standalone events เช่น roadside_shrine, old_woman_rice, tanee_grove, wandering_shaman, crying_child, old_well, night_funeral, silk_on_tree, fork_in_mist, temple_bell, boatman, spirit_medium_trance; อีก 7 รายการเป็นเนื้อหาจากโหมดเก่า ไม่ควรนำกลับมาโดยอัตโนมัติ

เรื่องหลัก run_story_1–3 ทุกเรื่องใช้ตัวเลือกเชิงกลไกเหมือนกัน: รับ 20 เบี้ย หรือเสีย 6 HP เพื่อรับ randomCard ดังนั้นเรื่องเปลี่ยน แต่การตัดสินใจคล้ายเดิมทุกคืน

**งานที่เสนอ:** คงเรื่องหลักบังคับไว้ แล้วเพิ่ม pool เหตุการณ์อิสระที่เข้ากับคืน/อาชีพ/สถานการณ์ สุ่มแบบ seeded ไม่ซ้ำใน run; เพิ่มผล follow-up เช่นช่วยชาวบ้านแล้วพบของ/ผี/ทางเลือกอื่นภายหลัง; ให้ทางเลือกบางอย่างเพิ่มหรือลดความกล้า/บุญอย่างมีเหตุผล

**เกณฑ์ตรวจ:** seed เดิมได้เส้นทางเดิม; แต่ละ event มีทางออกที่เลือกได้เสมอ; ไม่มีรางวัลกดซ้ำ; เคยเลือกทางไหนแสดงสัญญาณช่วยจำเมื่อพบอีกครั้ง; ไม่มีการเพิ่มหน้าเพียงเพื่อยืดเวลารัน

หลักฐาน: [adventure generator](https://github.com/saranaauttama-afk/PhiKinHuaV6/blob/bce58b93333e02e9ca214c0468e59bd5d89fada1/src/core/map/adventure.ts), [story event data](https://github.com/saranaauttama-afk/PhiKinHuaV6/blob/bce58b93333e02e9ca214c0468e59bd5d89fada1/src/data/packs/base/story_events.json)

### G06 — พรที่เปลี่ยนกฎการเล่นและมีราคาต่อเนื่อง (P1)

พรหลักมี trigger ทำงานระหว่างไฟต์แล้ว จึงไม่ใช่เกมไม่มี passive system สิ่งที่ยังตื้นคือแพนโดรา: 7 แบบทั้งหมดใช้ onGain, triggers ว่าง ผลส่วนใหญ่เป็น MaxHP แลกเงิน/AP/Mana/Draw/Retain/ช่องอุปกรณ์

NOTFM มีพรแบบเปลี่ยนรูปแบบมือหรืออุปกรณ์และมีผลเสียต่อการเล่น เช่นเพิ่มช่องอุปกรณ์แต่ลดไพ่เปิดไฟต์ หรือเพิ่ม hand size/slot แต่ทิ้งมือท้ายเทิร์น ดู [Pandora’s Box](https://night-of-the-full-moon.fandom.com/wiki/Pandora%E2%80%99s_Box), [Preparedness](https://night-of-the-full-moon.fandom.com/wiki/Preparedness) ระดับ B/C

**งานที่เสนอ:** เพิ่มพรเพียงชุดเล็กที่สร้างแผนใหม่ เช่น “ได้ประโยชน์จากการทิ้ง แต่เสีย retain”, “อุปกรณ์ทำงานแรงขึ้น แต่เปิดมือเล็ก”, “บทสวดแรงขึ้น แต่ใช้แต้มมากขึ้น”, “ยืมการ์ดได้เพิ่ม แต่มีผลเสียเมื่อใช้สำเนา” ทุกชิ้นต้องมีต้นทุนที่ผู้เล่นเห็นและเลือกยอมรับ

**โครง engine ที่ยังต้องต่อ:** TriggerOn มีเพียง battleStart/equip/turnStart/turnEnd/play/prayerDone; ถ้าต้องการผลตอน discard/exhaust/จบคืน ต้องเพิ่ม hook จริงก่อนเขียนข้อความสัญญาผลนั้น ไม่ย้อนกลับไปเป็นระบบคอมโบที่ติดตามลำดับ

**เกณฑ์ตรวจ:** ผลดี/ผลเสียใช้ทุกครั้งตามกติกา; แสดงข้อเสียก่อนเลือก; interaction ไม่สร้าง loop; ยังเล่นจบได้ทุกอาชีพ

### G07 — การเติบโตของทรัพยากรที่รองรับ build (P1/P2)

ของเรา AP/Mana/Draw เพิ่มได้ผ่านเอฟเฟกต์การ์ด, พร และบางสกิลอยู่แล้ว แต่รางวัลเลเวลสุ่มจาก card/upgrade/remove/slot/retain เท่านั้น; AP ถาวรผ่านแพนโดราปลดล็อกที่ 6 คืน; starting Mana เพิ่มได้จากบางพรและสกิลคนทรง

คู่มือคลาส NOTFM อธิบายการเลือกรางวัลเลเวลเกี่ยวกับ Equipment slots, Cards, Mana, Action, Gold/HP เช่น [Nun Guide](https://gamepretty.com/night-of-the-full-moon-nun-guide/) ระดับ B/C

**งานที่เสนอ:** ทำให้แต่ละอาชีพมีช่องทางปรับ resource engine ที่ชัดและเข้าถึงทันช่วง build ก่อตัว ผ่านเลเวล/พร/เหตุการณ์ตามอาชีพ ไม่จำเป็นต้องคืนพลังถาวรเข้าร้านที่เพิ่งถอดออก

**เกณฑ์ตรวจ:** ทุกอาชีพมีอย่างน้อยสอง build ที่เล่นต่างกัน; ต้องใช้ rarity/unlock จริงในการซิม; เพิ่ม resource แล้วตัดสินใจมากขึ้น ไม่กลายเป็นเล่นทุกใบได้โดยไม่มีต้นทุน

## 4. สิ่งที่ต้องจูนและวัดก่อนขยาย

### G08 — ความต่างอาชีพและระดับ 5 (P1)

handoff ของ commit นี้รายงานซิมอาชีพละ 20 รันต่อความยาก (รวม 80/ระดับ):

| ระดับ | รวมชนะ | นักรบ | คนทรง |
|---|---:|---:|---:|
| 1 | 88% | 100% | 70% |
| 2 | 68% | 95% | 40% |
| 3 | 65% | 85% | 40% |
| 4 | 62% | 70% | 50% |
| 5 | 12% | 10% | 5% |

ตัวเลขนี้เป็น **ผลที่ผู้พัฒนาบันทึกใน handoff** ไม่ใช่ผลซิมที่ผมรันใหม่ในการตรวจครั้งนี้ ตัวอย่างอาชีพละ 20 รันและบอทหนึ่งแบบยังไม่พอพิสูจน์ว่าอาชีพใดอ่อน/ง่ายสำหรับคนทุกระดับ

สิ่งที่ควรตรวจต่อ: opening hand ของนักรบ, แหล่ง resource ของคนทรง, โอกาสใช้ borrow ที่จำเป็นต้องรอผีเล่นก่อน, การตายที่เปรตวัดร้าง, และผลรวม draw cut กับบอสจริงในระดับ 5 แยกสาเหตุทีละกฎ

**งานที่เสนอ:** ซิมแยกอาชีพ/ระดับ/พร tier/เส้นบอส/การเก็บมือ + เล่นจริง โดยเปลี่ยนตัวเลขทีละสมมติฐานและวัดผล ไม่ลด passive นักรบอย่างเดียวโดยไม่ดูสำรับเริ่ม

### G09 — เป้าหมาย 60 นาทีและคุณภาพการเลือก (P2)

30–31 ไฟต์เป็นโครงที่มีอยู่จริงและตรงทิศทางรันสามคืน การเปรียบเทียบจำนวนศัตรู NOTFM จากแหล่งชุมชนต้องระวังตัวนับบอส/ฉบับ/DLC จึงไม่ควรเปลี่ยนจำนวนไฟต์ของเราเพียงเพื่อให้ตรงตัวเลขหนึ่งหน้าเว็บ

`RunMetrics` เก็บ turns, cardsPlayed, damageTaken, added/removed/upgraded แต่ไม่มี elapsed/active play time, เวลาหน้าเลือก, จำนวนครั้งที่เข้า/ปิดบริการ หรือเหตุผลการแพ้

**งานที่เสนอ:** เก็บเวลาที่เล่นจริงแยกจาก pause/background และแยกเวลาต่อสู้/รางวัล/หน้าเดินทาง ใช้ playtest ยืนยัน median ใกล้ 60 นาที; วัดความถี่การเข้าร้าน/ใช้จุดพักและขนาดเด็คตลอด run

**เกณฑ์ตรวจ:** สรุปเวลารันจริงได้; การเพิ่ม event ไม่ทำให้รันยาวโดยไม่มีการตัดสินใจเพิ่ม; UI รางวัลหลายชั้นไม่ขัดจังหวะซ้ำเกินไป

### G10 — การปลดล็อกและเหตุผลให้เล่นซ้ำ (P2)

มี difficulty progression แยกอาชีพ, ประวัติ, สารานุกรม และแพนโดราที่ปลดตามคืนแล้ว แต่การ์ด/พรเฉพาะอาชีพผูกกับการชนะระดับ 5 ทำให้แรงจูงใจแบบ “ผ่านทีละขั้นแล้วเห็นของใหม่” ยังมีช่องว่าง

**งานที่เสนอ:** milestone reward ระดับ 1–4 ที่เพิ่มทางเลือกแทนบวกพลังตรง ๆ และ achievement ตามอาชีพ เช่น prayer resolution, borrowed-card mastery, equipment build, curse control พร้อมบอกเงื่อนไขและความคืบหน้าใน UI

### G11 — Tutorial ของกติกาที่เพิ่ม (P2)

คลาสเลือกแล้วมีสกิล 3 ช่องพร้อมตั้งแต่ต้น run ขณะที่ NOTFM บางคู่มืออธิบาย unlock สกิลตามเลเวล เป็นความต่างที่ยอมรับได้ แต่เกมเราต้องช่วยสอน Action vs Mana, retain vs hand cap, Prayer delay, Counter และ equipped slots

**งานที่เสนอ:** คำแนะนำสั้นตอนพบครั้งแรกในรัน/โปรไฟล์, แสดงตัวอย่างค่าใช้จ่ายและผล, ไม่สร้างหน้าสอนยาวขัดรัน และไม่ต้องล็อกสกิลตาม NOTFM หากไม่มีเหตุผลของเกมเรา

## 6. สิ่งที่งานวิจัยไม่ควรถูกใช้เป็นข้อบังคับ

1. **เปิด intent ศัตรูล่วงหน้า:** รายงานเดิมมีข้อเสนอเชิง UX ปะปนกับคำอธิบาย NOTFM แต่ยังไม่มีหลักฐานมั่นคงว่า Classic แสดงชุดการ์ด/ดาเมจอนาคตแบบนั้น `phase6` ซ่อนการตัดสินใจจนเทิร์นผีและแสดงกฎ/History อยู่แล้ว จึงไม่จัด “ไม่มี intent ล่วงหน้า” เป็นระบบขาด และไม่เสนอคืนระบบนี้จากสมมติฐาน
2. **จั่วให้เต็มมือ vs จั่วเพิ่มจำนวนคงที่:** คู่มือออนไลน์มีถ้อยคำไม่สอดคล้องกัน และ hand size/draw/retain ถูกใช้คนละความหมายในบางแหล่ง ไม่ใช้ข้อมูลนี้เปลี่ยนกติกา 4 เปิดมือ / 2 จั่วเพิ่ม / 10 cap / 3 retain ของเราทันที
3. **แจกการ์ดทุก normal fight:** เป็นแนวทางของ deckbuilder บางแบบ ไม่ใช่ข้อเท็จจริงที่หลักฐานรายงานเดิมยืนยันครบสำหรับ NOTFM Classic จึงไม่ถือว่ารางวัล EXP/Gold ของ normal fight เป็นบั๊ก
4. **ตัวเลขร้าน/รางวัล/จำนวนศัตรู:** ต้องใช้เป้าหมาย pacing และเศรษฐกิจของผีกินหัวเป็นตัวตัดสิน
5. **คืน minion หรือ explicit combo:** ถูกถอดในทิศทางปัจจุบันแล้ว ความลึกเพิ่มได้จาก Prayer, Counter, Equipment, Borrow, Curse และ natural synergy ที่มีอยู่
6. **Normal/Hard dialogue เหมือนกัน:** NOTFM บางคู่มือแยกชัดว่า Courage/Reputation มีใน Normal ส่วนเกมเราตั้งใจใช้ความกล้า/บุญทุกระดับ ถือเป็นความต่างที่มีเหตุผลได้
